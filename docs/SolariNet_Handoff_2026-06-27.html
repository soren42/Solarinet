Resolved Punchdown Items

  • P0PHP/C bridge reply cap mismatch: resolved and covered by tests/dashboard/test_solari_ctl.php.
  • P1NodeDetail history wiring: remediated for CPU, RAM, and disk series. The adapter now consumes the route's actual series envelope.
  • P1Dashboard API contract drift: partially remediated for the history endpoint by making adapter and PHP response shape agree.
  • P1Deploy script validation gap: partially remediated with syntax validation. Full shellcheck remains blocked by missing local tool.

Still Outstanding

  • Live dashboard/browser/SSE acceptance: the code now builds and PHP routes lint, but a real browser-driven pass was not performed in this CLI environment. Next step: run the SPA against a seeded live DB and verify console, layout, auth, NodeDetail trends, and EventSource updates.
  • Live solariCtl round-trip acceptance: C and PHP tests are green, and the cap bug is fixed, but a running server plus real AF_UNIX bridge mutation round-trip should still be driven end to end before calling operator control fully accepted.
  • Network throughput history: NodeDetail still shows live throughput, but historical net series is not stored in hostHistory. Add rx/tx history columns or a derived history endpoint before marking net trends complete.
  • Static musl/MIPS build matrix: remains a product-build track. Current changes do not add static x86_64/arm64/arm32/mips/mipsel artifacts.
  • Container agent and agentless polling: still not implemented. These are needed for immutable appliances and fully closed devices.
  • macOS/Windows PALs: still unwritten; CI validates the portable core on those platforms, not running agents.
  • Remote CA forwarding: caMode=remote remains fail-closed in solariCtl.c.
  • SNMP deep topology backend: normalization is present and tested, but live SNMP fetch remains off-by-default and unimplemented.
  • Directory-service auth: local JSON auth works; LDAP/AD remains a fail-closed stub.

Operator Notes

  • The PHP bridge can now receive the full C bridge reply size, but deployments should still monitor web-server/FPM timeouts for long mutation paths.
  • NodeDetail history now issues three additional history calls per viewed node on load and every 10 seconds. The calls are bounded by the existing history route limit and only run on the detail screen.
  • The dashboard still gracefully falls back to offline fixture mode when the live API is unreachable; authentication failures continue to show the login gate instead of silently serving demo data.
