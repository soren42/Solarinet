Phase 7 deliverables

Topology — deep path (server)

src/server/serverTopology.c gained a deep-discovery path that normalizes LLDP-MIB rows into the schema's gear/edge model and assembles the /api/netgear view — all pure and SNMP-free in the default build:

  • LLDP-MIB normalization. One decoded lldpRemTable row (topoLldpMibRecord) becomes a serverNetGear + a serverLldpEdge (topoNormalizeMibRecord). Gear-kind inference (topoInferGearKind) treats the LLDP SystemCapabilitiesMap bits as authoritative (AP > router > bridge), falling back to sysName / sysDesc keyword matching when caps are absent. Gear IDs (topoMibGearId) are stable and kind-prefixed (sw-/ap-/gw-/rtr-/nd-), seeded sysName → mgmtIp → chassisId. A C99-safe case-insensitive substring (topoContainsCi) avoids GNU strcasestr.
  • Uplink-chain + attached-count assembly. topoAssembleNetGear de-duplicates gear by gearId, counts DISTINCT attached SolariNet nodes per gear (gear-to-gear edges excluded; a node seen on multiple interfaces counts once), and computes uplink depth with a cycle guard (TOPO_MAX_UPLINK_HOPS). Returns ERR_BUFFER_FULL on an undersized output buffer.
  • Two projections. /api/topology serves view=monitoring (from HRW + node data) and view=network (from networkGear + lldpEdge + the assembled uplink chain).
SNMP capabilities are optional. With SOLARI_WITH_SNMP=ON, the LLDP topology fetch (topoSnmpFetchLldp) walks LLDP-MIB columns with the net-snmp CLI, then feeds the tested normalizer; the IF-MIB poller stores interface counters in gearInterfaceCurrent and gearInterfaceHistory. Both fetch paths return ERR_PLATFORM in the default build. The option is off by default and adds no SNMP library build dependency, but requires snmpbulkwalk at runtime. Neither path has been verified against a live network device in this release candidate. The IF-MIB walk parser now rejects malformed numeric OIDs, invalid or out-of-range values, and interface names that would otherwise be silently truncated; tests pass with the feature both off and on. A fake CLI integration fixture exercises LLDP column collection, normalization, and nonzero-command failure handling without contacting a device.

API / control-plane discipline

There are three operator surfaces — the dashboard PHP API, the MCP, and the solariCtl Unix socket — and they share one discipline:

  • Reads are direct, control is routed. Read endpoints project the database. State-changing actions never write the DB from the edge surface; they are handed to the C server (via solariCtl), which stays the single arbiter.
  • Destructive actions require an operator token and explicit confirmation. Approve-enrollment (signs a CSR) and decommission (wipes a node) refuse before any network call unless both the operator token and an explicit confirm=true are present. Decommission uses a stored SHA-256 digest of a random one-time confirmation token, bound to node, wipe scope, operator, and a ten-minute expiry. The server consumes it and retires the node in one transaction; raw tokens are never written to audit details.
  • solariCtl verbs: PING, SURVEY, APPROVE/REJECT, PROVISION, ADOPT, IGNORE, CONTROL, DECOMMISSION/RETIRE.

Enrollment runbook

deploy/enrollment/solari-enroll.sh enrolls a node end-to-end, generating key material locally and only ever sending a CSR:

  1. Generates an EC P-256 key + CSR locally (--rsa for an RSA key). The CN encodes role.fqdn so the role is the leading DNS label used by server ingest authorization (e.g. CN=monitor.beryl.akoria.net); the FQDN is also in the DNS SAN.
  2. Submits {token, role, fqdn, certFp, csrPem} to the server — over HTTPS (--server) or a local solariCtl Unix socket (--ctl-socket).
  3. Handles the status=pending reply (awaiting operator approval).
  4. On approval, installs the signed cert + CA root, verifies the chain, and stamps nodeId into [identity] of the node config.
# enroll a monitor against the server over HTTPS
deploy/enrollment/solari-enroll.sh --role monitor --fqdn beryl.akoria.net \
    --token "$ENROLL_TOKEN" --server https://server.akoria.net

# generate key + CSR only (no submission) — useful for offline / staged enrollment
deploy/enrollment/solari-enroll.sh --role monitor --fqdn beryl.akoria.net --csr-only

Key flags: --role, --fqdn, --token, --server / --ctl-socket, --rsa / --key-bits, --csr-only, --conf-dir / --config, --insecure, --force.

Verified: --csr-only produced a real EC key + CSR whose openssl req -verify returns "self-signature verify OK" (subject=CN=monitor.beryl.akoria.net).

Decommission runbook

The dashboard issues a durable decommission challenge on the first queued request. The second request supplies that same token; the server checks its stored digest, node, wipe scope, operator, and expiry before consuming it and publishing a directive with the challenge generation. The node remains active until an authenticated success result echoes that generation. Expired, mismatched, replayed, or force-cancelled challenges fail. The active server persists delivery attempts and retries from 5 seconds up to a 5-minute interval until acknowledgement or cancellation, including after restart or failover. The client currently has no receiver for this directive, so remote teardown still cannot complete. The privileged request queue also retains the raw confirmation token in its request/result text. Do not treat a sent directive as a completed wipe. deploy/enrollment/solari-decommission.sh remains a separate node-local, operator-driven executor (Handoff §4.2 / §7.3), not an SCP message receiver:

  1. Requires a server-issued --confirm-token (TLV_LIFE_CONFIRM) echoed for audit, plus an interactive phrase confirmation.
  2. --wipe-scope config,certs,spool,logs,unit,all (TLV_LIFE_WIPE_SCOPE) selects what is erased.
  3. Stops the service, reports retirement best-effort before key deletion, securely erases the scoped material (shred when available), then disables / removes the unit.
  4. --dry-run to rehearse; --local-force --yes for an offline or forced teardown when the server is unreachable.
# server-driven, audited teardown of a node
deploy/enrollment/solari-decommission.sh --confirm-token "$TOKEN" --wipe-scope all
# rehearse without touching anything
deploy/enrollment/solari-decommission.sh --confirm-token "$TOKEN" --wipe-scope config,certs --dry-run

Verified: scope parsing and a full --dry-run exit cleanly (rc=0); both scripts pass bash -n.

Retention & history rolling

db/maintenance/ holds MariaDB stored procedures that operationalize the TO_DAYS(sampledAt) RANGE partition scheme from db/schema.sql:

  • retention.sql — solari_purge_retired / solari_purge_pending_controls / solari_purge_history / solari_retention_run: expire unanswered control directives after seven days, purge state='retired' nodes (with FK-cascade children plus explicit nodeConfig / hostHistory) past the retention window, with a row-level history safety net.
  • roll_history.sql — solari_roll_partitions: REORGANIZE the p_max catch-all into monthly pYYYYMM partitions ahead of now and DROP-PARTITION months aged past retention, on both hostHistory and probeHistory. Idempotent via information_schema.PARTITIONS guards; dynamic DDL via PREPARE/EXECUTE.

Schedule them from cron / an event scheduler, e.g. CALL solari_retention_run(...) nightly and CALL solari_roll_partitions(...) monthly. The procedure is installed in the candidate and scratch-tested; an active cron, event, or systemd schedule on the current host has not been verified.
