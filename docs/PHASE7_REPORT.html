What landed in Phase 7

Topology depth — serverTopology.c

The shallow self-report path (a node naming its own uplink) is extended with a deep managed-gear path: pure, testable normalization of LLDP-MIB neighbour records into networkGear / lldpEdge rows, gear-kind inference (gateway/switch/ap/router from LLDP capability bits, falling back to sysName/sysDesc keywords), stable gearId derivation, and uplink-chain assembly with attached-node counts and a cycle guard for /api/netgear. The actual SNMP fetch — the most environment-specific piece — is isolated behind an off-by-default SOLARI_WITH_SNMP seam, so the default and server builds add no net-snmp dependency and still compile everywhere. Nine unit tests were added (test_server_topology now exercises 13 cases).

MCP catch-up — integrations/mcp/

The FastMCP server is brought in step with the new §6 endpoints and §5 tables: 13 new tools (14 → 27) covering discovery / enrollments / builds / segments / netgear / topology-view / config reads plus guarded control actions (adopt, ignore, approve, reject, provision, decommission). The destructive tools (approve_enrollment, decommission) require an operator token and an explicit confirm before any network call, mirroring the dashboard's control discipline. The read-only SQL surface gains a table allow-list including the new C2 tables (segment, networkGear, lldpEdge, discovered, enrollment, buildArtifact), blocking information_schema/mysql exfiltration while preserving SELECT-only discipline. Tests against an in-memory mock: 81 passed.

CI reconciliation — getting the pipeline green

The CI workflow authored in Phase 7 was correct on the development host but failed on fresh GitHub runners. Every failure shared a single theme: the committed, portable tree carried something the local working tree had been hiding. Four CI runs walked the failures down to zero. The progression:

RunCommitResultSurfaced
…607255e02893bfailUnity macros undefined (TEST_ASSERT_BITS_HIGH/LOW, …EQUAL_STRING_LEN)
…7281749357d9afailunity_internals.h: No such file
…787878ca87da4partialarm32 64-bit asserts; macOS/Windows missing PAL
…96927505117d4all green—

1 · Unity 2.6.0 not fully in the committed history

The protocol/platform tests use TEST_ASSERT_BITS_HIGH/LOW and TEST_ASSERT_EQUAL_STRING_LEN, which only exist in the full Unity 2.6.0. That upgrade had been committed locally but not pushed, so the first CI run built against the older minimal shim and the macros were implicit-declaration errors under -Werror. Fix: push the Unity 2.6.0 vendor commit (9357d9a).

2 · unity_internals.h excluded by a stale ignore rule

Full Unity's unity.h does #include "unity_internals.h", but a leftover .gitignore line from the minimal-shim era (/third_party/unity/unity_internals.h) kept that file untracked. Local builds passed only because the file existed on disk; a fresh checkout had no such file and failed at the first compile. Fix (ca87da4): remove the ignore rule and commit the header. Verified by building from a tracked-files-only export to mirror exactly what CI checks out.

3 · arm32 — “Unity 64-bit Support Disabled”

The cross-build succeeded but the qemu-user smoke run aborted: the uint64 TLV/frame assertions need UNITY_SUPPORT_64, which Unity auto-enables on 64-bit hosts but disables on 32-bit ABIs like arm32. Fix (05117d4): define UNITY_SUPPORT_64 PUBLIC on the unity CMake target, so every suite gets 64-bit assertions on every ABI (a no-op on the already-64-bit hosts, confirmed by the unchanged 22/22 native result).

4 · macOS / Windows — no PAL for those OSes yet

Only plat/platLinux.c exists; platMacos.c and platWindows.c are deferred future steps. The client's CMake listed the missing source, so add_library() hard-failed at configure time — and because the client sub-directory is always added, that broke the whole tree on those OSes. Fix (05117d4):

  • Added SOLARI_BUILD_CLIENT / SOLARI_BUILD_MONITOR options (default ON), gating the component sub-directories.
  • Made the client self-skip when its target-OS PAL source is absent (a clean message(STATUS …) + return() instead of a hard error), so the portable libsolari core still configures and builds there.
  • Scoped the macOS and Windows-cross CI jobs to the portable core + Unity suites (client/monitor off) — which is Phase 0's actual cross-build acceptance criterion — while Linux arm64/arm32 continue to build the full tree.
Net CMake additions. Two build options (SOLARI_BUILD_CLIENT, SOLARI_BUILD_MONITOR), a PAL-presence guard in src/client/CMakeLists.txt, and UNITY_SUPPORT_64 on the test framework. The pre-existing test target guards (if(TARGET clientcore) / monitorcore / servercore) already cause the dependent suites to follow the components, so no test wiring changed.

Live acceptance (post-Phase 7)

The earlier "authored-correct but not run against a live DB/browser" caveat was then closed for the data layer by standing up a real MariaDB (Docker mariadb:11.8) and driving both tiers against it.

Track A — MariaDB & serverDb

  • db/schema.sql + migrations/001 + 002 applied to a live server with zero errors/warnings; the 002 ALTERs verified (node.segId/uplinkGearId, state enum gains retired, probeTarget.label/segId) and history partitions present.
  • New self-skipping integration suite tests/integration/test_server_db_live.c (linked against the real servercore; runs only when SOLARI_TEST_DB is set) drove the actual prepared statements: 7/7 pass — node upsert/touch/state, the hostCurrent+hostHistory client-report txn, alert/audit rows, discovered (ip,kind) upsert, the enrollment state machine, and the lease-claim election. Rows confirmed by direct SELECT. Column/placeholder alignment is now validated at runtime.

Track B — dashboard API & control plane

  • Served the SPA + PHP API from one origin against the live DB (after installing pdo_mysql). The shell + vendored runtime/fonts serve 200 with correct content-types, and all 12 read endpoints returned {ok:true} — exercising the real SQL, the §6 amendments (/api/probes label/replFactor/rolled-up state/vantages), segment rollups, the network gear hierarchy, and the summary counts+lease shape the adapter consumes.
  • Control-plane gating verified end-to-end: viewer 403 → operator-without-confirm 409 → empty wipe-scope 400 → operator+confirm+scope reaches the solariCtl bridge and degrades cleanly to 502 control_unavailable when no live socket is present. PHP never touches CA material.
  • A labelled fixture db/seed/demo.sql (the SQL parallel of data.jsx) drives this; documentation IP ranges, idempotent.

Known gaps & deferred items

  • Live solariCtl round-trip & browser visuals still pending. Mutating actions were validated up to the bridge boundary (gating + graceful failure), but a real control round-trip needs the server's accept/dispatch main loop, which remains stubbed pending bound sockets. Pixel-level SPA rendering / SSE was not driven in a browser here (no browser on-host; the no-Node policy rules out a bundled one) — visual acceptance is the remaining operator step.
  • macOS / Windows clients & monitors. platMacos.c and platWindows.c remain unwritten; those CI jobs validate only the portable core. Building the agents on those OSes is a future PAL step.
  • Deep gear discovery is opt-in. The SNMP/LLDP-MIB walk lives behind SOLARI_WITH_SNMP (off by default, no net-snmp linked). The normalization logic is tested; the live SNMP backend is not.
  • shellcheck not run. Deploy scripts passed bash -n only; deeper shell linting is recommended in a future CI step.
