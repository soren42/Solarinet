These items are product functionality needed to bring the full application online across the intended fleet and operator workflows.

PriorityFeatureStatusFinish CriteriaEvidence
P0control
Live control-plane round trip.
Dashboard and MCP mutations are not fully accepted until a real server bridge dispatch is exercised.
 With a running server, prove approve/reject, provision, adopt/ignore, survey, deploy, decommission first/final step, and failure paths all complete or fail correctly. Phase 7 says control was validated only to the bridge boundary and live round-trip remains pending.
P0dashboard
Browser visual acceptance and SSE behavior.
The application cannot be considered online for operators until the actual SPA is loaded and driven.
 Run the dashboard against demo and live DB data, confirm auth, navigation, polling, SSE events, responsive layout, service worker registration, and no console errors. `docs/PHASE7_REPORT.html:238-243` calls pixel-level SPA rendering and SSE a remaining operator step.
P0portabilityops
Static musl build matrix for appliances.
Required for MIPS, musl, and library-less network appliances.
 Publish tested x86_64, arm64, arm32, mips, and mipsel static agents and have `remote-deploy.sh` select them automatically. Handoff names static musl as recommended next; deploy script warns current glibc dynamic binaries will not run on musl/no-package-manager hosts.
P1portability
macOS and Windows client/monitor PALs.
Current cross-platform CI proves portable core only, not agent functionality.
 Implement `platMacos.c` and `platWindows.c`, then enable agent builds and PAL tests in those CI jobs. `src/client/CMakeLists.txt:10-26` skips absent PALs; Phase 7 says macOS/Windows agents remain unwritten.
P1opsportability
Container-agent deployment path.
Unblocks immutable but container-capable appliances such as ZimaOS.
 Build an agent image with host `/proc`, host networking, and writable config/cert volume support; add a dashboard/CLI deploy path. Handoff lists container agent as tier 2 for immutable container hosts (`docs/SolariNet_Handoff_2026-06-26.html:145`).
P1ops
Agentless managed-node polling.
Needed for devices that cannot run a SolariNet binary or container.
 Add SNMP, SSH-exec, or vendor API polling and model the result as a managed node or asset class distinct from reporting agents. Handoff lists SNMP/SSH/UniFi-controller API polling as tier 3 for closed devices.
P1control
Client-side WELCOME parser and schedule/config convergence.
Makes server-assigned epoch and schedule meaningful on nodes.
 Parse WELCOME TLVs, update runtime schedule, detect assigned-role mismatch, and request/apply config convergence when epoch drifts. `serverMaster.c` emits schedule TLVs while noting the node-side parser is still future work.
P1control
Asynchronous CSR approval delivery for enrollment script.
Completes the token/CSR enrollment lifecycle without manual cert handoff.
 After approval, store signed cert, let enrolling node retrieve it, verify chain, and write nodeId/config atomically. Handoff says approve/sign works but async approve-to-client retrieval remains outstanding.
P1control
Remote CA forwarding.
Allows the CA to move off the C2 host without breaking enrollment.
 Implement `caMode=remote` CSR forwarding, authentication, timeout/error handling, and audit logging. `src/server/solariCtl.c:949-951` refuses `caMode=remote` as not implemented.
P1topology
Real SNMP/LLDP-MIB backend for deep gear discovery.
Turns tested normalizers into live topology enrichment.
 Implement `topoSnmpFetchLldpImpl`, add opt-in dependency handling, credentials/config, live integration tests, and operator docs. `src/server/serverTopology.c:512` returns `ERR_PLATFORM` without `SOLARI_WITH_SNMP`; Phase 7 says live SNMP backend is not done.
P1dashboard
Node history chart verification with real history data.
The UI has code for history; the older handoff called the charts unwired, so this needs acceptance against live `hostHistory` rows.
 Seed or collect history, load `NodeDetail`, verify CPU/RAM/net/disk series scale correctly and refresh without dropping state. Handoff listed NodeDetail history as outstanding; current `api.jsx` and `nodes.php` implement loaders, so this is now an acceptance item.
P2dashboard
Directory-service authentication.
Required for multi-operator environments that do not want local JSON credentials.
 Implement LDAP/AD bind, role mapping, error handling, and tests while keeping local auth as fallback. `dashboard/api/lib/Auth.php` exposes the config surface but always denies directory auth.
P2ops
MIPS and mipsel remote deploy artifacts.
Installer already recognizes these arches, but no binary path exists yet.
 Build, smoke-test, and publish `deploy/dist/mips/solariClient` and `deploy/dist/mipsel/solariClient` or static equivalents. `remote-deploy.sh` normalizes MIPS arches but `cross-build-client.sh` supports only arm64, arm32, and x86_64.
P2dashboardops
Production-ready remote deploy UX.
Makes dashboard-based installs usable without falling back to terminal logs.
 Show active job state, streaming/tailing log, failure reason, chosen binary, target probe results, and next action. Current PHP route starts deploy and exposes a log tail endpoint; handoff says log visibility needs improvement.
P2ops
End-to-end production install runbook validation.
Confirms the full app comes online from fresh host to live dashboard.
 Automate or document a fresh install that applies schema/migrations, starts services, creates admin credentials, deploys one client, and verifies dashboard/MCP/API health. Docs provide pieces, but remaining acceptance items are still described as operator steps across Phase 6 and Phase 7.
