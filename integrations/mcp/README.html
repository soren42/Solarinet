solarinet_mcp

An MCP server that gives an LLM agent eyes — and a careful set of hands — on a SolariNet deployment.

This server exposes three surfaces of the SolariNet monitoring system to an agent: the read-only dashboard API (§11.2), the operator control plane (survey / config push), and fixed read-only database views over the MariaDB schema (§10). It is written in Python with FastMCP — no Node, per project policy — and ships with unit tests and a verifiable evaluation suite.

Release boundary. This candidate exposes published dashboard API operations and fixed database views. Generic caller-supplied SQL is not exposed as a tool. Unit tests use injected API and DB fixtures; run the project integration suite separately to verify deployment behavior.

Install

cd integrations/mcp
pip install -r requirements.txt        # or: pip install -e .
python -m solarinet_mcp --check        # prints config + the 26 tools, no server start

Safety model

  • Read vs. write are clearly separated and annotated (readOnlyHint/destructiveHint) so clients can gate the eight control tools.
  • Database access uses fixed query functions. MCP callers cannot supply SQL. The internal DB client still enforces read-only syntax, a table allow-list, and row caps; pair it with a SELECT-only DB grant for defense in depth.
  • No secrets in source. All credentials come from the environment, matching SolariNet's own §13 convention.

Test & verify

cd integrations/mcp
python -m pytest -q              # MCP unit tests
python evals/check_answers.py    # derives and verifies all 10 answers through tools and fixtures

The evaluation questions live in evals/evaluation.xml; they're read-only, independent, and verify to stable answers against the fixture in evals/fixture.py.

For module responsibilities, tool contracts, runtime configuration, and security boundaries, see the MCP Developer Reference.
