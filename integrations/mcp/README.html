solarinet_mcp

An MCP server that gives an LLM agent eyes — and a careful set of hands — on a SolariNet deployment.

This server exposes three surfaces of the SolariNet monitoring system to an agent: the read-only dashboard API (§11.2), the operator control plane (survey / config push), and read-only SQL over the MariaDB schema (§10). It is written in Python with FastMCP — no Node, per project policy — and ships with unit tests and a verifiable evaluation suite.

Status. The SolariNet REST API (Phase 6) and live MariaDB aren't built yet, so this server targets the documented §11.2 contract and §10 schema and is validated against an in-memory mock of both. Point it at the real dashboard/DB by setting the environment variables below — no code changes needed.

Install

cd integrations/mcp
pip install -r requirements.txt        # or: pip install -e .
python -m solarinet_mcp --check        # prints config + the 14 tools, no server start

Safety model

  • Read vs. write are clearly separated and annotated (readOnlyHint/destructiveHint) so clients can gate the two control tools.
  • The DB layer never writes. A guard rejects anything but a single SELECT/WITH statement — no DML/DDL, no stacked statements, no INTO OUTFILE/DUMPFILE — strips comments before analysis, and caps returned rows. Pair it with a SELECT-only DB grant for defense in depth.
  • No secrets in source. All credentials come from the environment, matching SolariNet's own §13 convention.

Test & verify

cd integrations/mcp
python -m pytest -q              # 43 unit tests (REST via mock transport, SQL guard, DB, formatting)
python evals/check_answers.py    # verifies all 10 evaluation answers via the tools

The evaluation questions live in evals/evaluation.xml; they're read-only, independent, and verify to stable answers against the fixture in evals/fixture.py.

        "SOLARINET_DB_USER": "solari_ro",
        "SOLARINET_DB_PASS": "…"

  }
}
