Dashboard ↔ API Reconciliation

Claude Design handoff (window.SOLARI mock) vs. the §11.2 REST contract & §10 schema — what lines up, what needs adapting, and what the contract still owes the UI.

Import shape. The design is in-browser React 18 + Babel (no Node build), with a seeded mock data layer in data.jsx exposing one global object, window.SOLARI. The cleanest wiring (Phase 6) keeps that object as the UI's internal model and adds a single api.jsx adapter that fetches the §11.2 endpoints and populates the same shape — so every screen keeps working unchanged. data.jsx stays as the offline/demo fixture.

3 · Cross-cutting issues to resolve

On-prem / no-cloud tenet (§1)

The design loads React, ReactDOM, and Babel from unpkg.com and fonts from fonts.googleapis.com at runtime. That conflicts with the "local control, no cloud dependency" tenet for an air-gapped intranet — the C2 must work with no internet. Action: vendor React/ReactDOM/Babel into dashboard/public/vendor/ and self-host the IBM Plex fonts; repoint index.html at local paths.

In-browser JSX transpile

Babel-standalone transpiles the .jsx in the browser on every load — convenient (and consistent with the no-Node rule), but it adds first-paint latency and ships the whole compiler. Acceptable for an internal tool; if load time bites, the only faster path is pre-transpiling, which needs a build tool (Node) we're avoiding — so plan to keep in-browser Babel unless that changes.

PWA without a service worker

manifest.webmanifest + icons make it installable, but there's no registered service worker, so it isn't offline-capable yet. Add a sw.js if an operator should keep the last C2 view during a server blip.

Units & time

The UI thinks in percentages and "minutes ago"; the API speaks raw KB/milli and ISO-8601 UTC. Keep all conversion in the api.jsx adapter (the existing SOLARI.fmt helpers already format for display), so the wire stays canonical and the UI stays pretty.

4 · Suggested Phase 6 order

  • Vendor front-end deps locally (on-prem fix) — quick, unblocks air-gapped use.
  • Write api.jsx adapter → light up the three built screens against the existing endpoints (/api/nodes, /api/probes, /api/alerts, /api/server/status).
  • Stand up the PHP PDO read layer + those endpoints + the SSE bridge (§11.1).
  • Extend the contract for the placeholder screens: /api/rules, /api/segments, /api/summary, then discovery/enrollment/builds/netgear as those subsystems land server-side.
